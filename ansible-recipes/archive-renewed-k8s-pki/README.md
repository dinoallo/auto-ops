# Archive Renewed Kubernetes PKI

Chinese version: `README.zh-CN.md`

This recipe archives active Kubernetes PKI files and promotes renewed,
date-hour-stamped files back to the canonical kubeadm file names.

It supports three PKI scopes:

- `root`: Kubernetes root CA, API server leaf certificates, and system kubeconfigs
- `front-proxy`: front-proxy CA, bundle, and front-proxy client certificate
- `etcd`: etcd CA, bundle, and etcd leaf certificates

By default, the playbook also rewrites kube-apiserver, kube-controller-manager,
and/or etcd static Pod manifests back to the canonical kubeadm file paths for
the selected scope. Set `canonicalize_manifests=false` only when another
playbook or a manual step already converges the manifests.

For the final cutover/archive phase, run this playbook after the compatibility
and leaf-certificate activation steps, instead of running a scope-specific CA
activation playbook that already promotes the staged CA files. Running both for
the same scope is normally unnecessary because the staged CA filenames are moved
to the canonical names during promotion.

When `promotion_scope` includes `front-proxy`, `canonicalize_manifests` is `true`, and `restart_metrics_server` is `true`, the playbook also waits for kube-apiserver to republish the `extension-apiserver-authentication` ConfigMap and then performs a rolling restart of the `metrics-server` Deployment. This ensures metrics-server reloads the front-proxy CA and trusts the new aggregator client certificate.

## Usage

Promote all supported scopes for the current-hour default renewal ID:

```bash
ansible-playbook \
  -i inventory.ini \
  ansible-recipes/archive-renewed-k8s-pki/playbook.yml \
  -e restart_static_pods=true
```

Promote only front-proxy files generated with an explicit renewal ID:

```bash
ansible-playbook \
  -i inventory.ini \
  ansible-recipes/archive-renewed-k8s-pki/playbook.yml \
  -e promotion_scope=front-proxy \
  -e renewal_id=2026062208 \
  -e restart_static_pods=true
```

Promote all scopes generated by a second rotation within the same hour:

```bash
ansible-playbook \
  -i inventory.ini \
  ansible-recipes/archive-renewed-k8s-pki/playbook.yml \
  -e renewal_id=2026062208-2 \
  -e restart_static_pods=true
```

## Defaults

Renewal playbooks now write staged files with a date and hour in the file name. With the
default `renewal_id=YYYYMMDDHH`, this playbook expects names such as:

- `/etc/kubernetes/pki/ca-new-2026062208.crt`
- `/etc/kubernetes/pki/front-proxy-ca-new-2026062208.crt`
- `/etc/kubernetes/pki/etcd/ca-new-2026062208.crt`
- `/etc/kubernetes/pki/etcd/server-new-2026062208.crt`

The active files are copied into an archive directory before each renewed file
is moved to the active name. If a renewed source already matches the active
destination, the duplicate source is removed without archiving the destination
again. Default archive directories are:

- `/etc/kubernetes/pki/archive/root-<renewal_id>`
- `/etc/kubernetes/pki/archive/front-proxy-<renewal_id>`
- `/etc/kubernetes/pki/archive/etcd-<renewal_id>`

Archive files use the suffix `<ansible_date_time.iso8601_basic_short>.bak`.

## Variables

- `promotion_scope`: `all`, `root`, `front-proxy`, or `etcd`. Default: `all`.
- `renewal_id`: shared date-hour or custom ID used by renew and promotion
  playbooks. Default: the target host date and hour as `YYYYMMDDHH`.
- `archive_suffix`: archive file suffix. Default:
  `<ansible_date_time.iso8601_basic_short>.bak`.
- `archive_promote_serial`: rollout serial for each scope. Default: `1`.
- `require_active_files`: fail when an active destination is missing. Default:
  `true`.
- `require_renewed_sources`: fail when no renewed sources for the selected scope
  exist. Default: `true`.
- `canonicalize_manifests`: rewrite static Pod manifest certificate arguments
  to canonical kubeadm paths after promotion. Default: `true`.
- `restart_static_pods`: touch changed static Pod manifests after canonicalizing
  paths. Default: `false`.
- `restart_metrics_server`: rollout restart the metrics-server Deployment
  after promoting front-proxy PKI so it reloads the front-proxy CA from the
  `extension-apiserver-authentication` ConfigMap. Default: `true`.
- `metrics_server_namespace`: namespace of the metrics-server Deployment.
  Default: `kube-system`.
- `metrics_server_deployment`: name of the metrics-server Deployment.
  Default: `metrics-server`.
- `metrics_server_rollout_timeout`: timeout passed to `kubectl rollout status`.
  Default: `300s`.
- `kubeconfig`: kubeconfig file used for kubectl commands during the
  metrics-server restart. Default: `/etc/kubernetes/admin.conf`.
- `kubectl_retries`: retry count when waiting for kube-apiserver to publish the
  updated `extension-apiserver-authentication` ConfigMap. Default: `30`.
- `kubectl_delay`: seconds between kubectl retries. Default: `10`.
- `remove_duplicate_sources`: delete a renewed source when it already matches
  the active destination. Default: `true`.
- `root_target_hosts`, `front_proxy_target_hosts`, `etcd_target_hosts`: target
  host patterns for each scope.
- `root_archive_dir`, `front_proxy_archive_dir`, `etcd_archive_dir`: override
  archive directories.
- `root_promotions`, `front_proxy_promotions`, `etcd_promotions`: override the
  default promotion file lists. Each item must contain `label`, `src`, and
  `dest`.

## Notes

Use the same `renewal_id` across the renew, configure, audit, kubelet,
leaf-certificate activation, and archive/promote playbooks when a rotation spans
multiple hours or when you run more than one rotation within the same hour.
